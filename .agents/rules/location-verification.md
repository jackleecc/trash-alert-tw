# 專案規則：新地點加入與清運資料驗證規範 (Location Onboarding Standard)

## 核心準則 (Core Mandate)

> **日後任何新地點加入，務必先確認撈得到該地點的歷史實際清運資料，才算真正加入地點成功。**
> 嚴禁僅憑官方靜態站名或地圖推估座標即宣告加入完成。

---

## 標準作業程序 (SOP)

當需要為新社區、站點或行政區開通到站推播服務時，必須依序完成以下 4 步驗證關卡：

### 1. 歷史實際清運動態撈取驗證 (Historical Data Verification)
* **檢核目標**：確認外部系統或環保局 API 能實際檢索到該地點的歷史收運實績。
* **必要檢驗欄位**：
  * **實際到站時間戳記**（如 `19:48:31 已到達`，非僅表定時間）
  * **真實執勤車號 / 車牌**（如 `218-UW`）
  * **清運狀態與類別**（如一般垃圾車 `cartype: 'N'`、非僅資收車）
  * **站點真實 GPS 座標比對**（比對經緯度誤差 $\le 50\text{m}$）
* **驗證未通過之處理**：若官方開放資料端點無該轄區/路段之動態（如台南 SOA 舊端點缺乏永康資料），必須查調或介接正確之即時系統（如 `clean.tnepb.gov.tw` 天眼 WebService），直到取得真實歷史清運記錄為止。

### 2. 智慧到站演算法相容性測試 (Algorithm Validation)
必須在 `test/` 目錄建立或擴充該地點之專屬測試套件，驗證 5 大核心演算法在該地點拓撲下的正確性：
1. **自適應空間圍欄 (Adaptive Geofence)**：依相鄰站距檢驗半徑（密集巷弄自動收縮至 120m，避免鄰近道路串擾）。
2. **班表時間窗 (Schedule Window)**：以實際歷史到站時間驗證是否順利放行，並確認提前路過與收班返隊能被正確攔截。
3. **360° 法定進場方位角 (Approach Bearing)**：推導站點進場向量，確保同向收運放行、逆向路過阻斷、停靠靜止漂移豁免。
4. **時速過濾 (Drive-by Speed Filter)**：慢速收運作業（$\le 25\text{km/h}$）放行，快速巡航巡弋阻斷。
5. **車種精準過濾 (Waste Type Precision)**：確保一般垃圾車發送，資源回收車自然靜音。

### 3. 資料庫登錄與訂閱設定 (Database Integration)
確認資料獲取與演算法有效後，方可登錄至 Supabase：
* `routes`：路線 ID、名稱、歸屬縣市、出車日 (`active_days`)。
* `stops`：站點 ID、名稱、WGS84 座標、表定時間。
* `line_groups` 與 `subscriptions`：綁定目標群組。

### 4. 產出建置與驗證報告 (Documentation)
於 `docs/reports/` 建立專屬報告（如 `location-report-<地區>-<地點>.md`），完整記錄：
* 站點經緯度與周邊拓撲。
* 撈取到的真實歷史清運數據佐證（車牌、實際到達時間戳、路線代碼）。
* 演算法單元測試涵蓋與驗證結果。
