# 新北官方清運網站作為同輪路線備援

新北開放資料可能連線成功卻只提供過期、其他路線的車輛資料，單純依縣市連線熔斷無法補上仍有活躍訂閱的路線。使用者同意讓 Truck Intake 在旗標啟用後，針對本輪所需新北路線的主來源失敗、缺漏或超過五分鐘樣本，同輪 POST 官方網站 GetArrival；保留有效主來源、只填缺口，並沿用到站判斷及通知護欄。新北仍是一個使用 canonical 主 URL 的邏輯來源，將主／備結果留作診斷，避免 City Pause Status 在同輪收到互相矛盾的成功與失敗。

網站頂層 TimeStamp 只能記為回應時間，Diff 是班表偏差；兩者都不能充當逐車 GPS 採樣時間。原決策為避免把新回應中的舊座標視為新車輛，將 `NTPC_WEBSITE_BACKUP_ENABLED` 預設 false，正式啟用另需服務時段位置更新與延遲佐證、驗證報告及使用者核准。這個保守門檻可能暫時留下漏報缺口；使用者已知悉並接受，不能以保證不漏報取代證據。無新增地點或資料庫 schema，完整介面與驗證條件見 [正式規格](../specs/ntpc-website-backup.md)。

## 2026-10-17 更新：預設啟用

使用者要求「直接把上次的備援寫進去」，取代原先等待採樣後才改變程式預設的分階段安排。環境旗標未設定時改為啟用，精確 `true` 啟用，精確 `false` 及其他字串關閉；明確 boolean 呼叫選項仍優先，回滾須明確設 `false`。保留原有補缺口與通知護欄，未包含正式部署。連續位置更新與逐車 GPS 延遲證據仍未取得，回應時間不得冒充 GPS 時間；新預設不代表已完成服務實證。具體範圍與驗收見 [預設啟用變更規格](../specs/ntpc-backup-default-enable.md)。
