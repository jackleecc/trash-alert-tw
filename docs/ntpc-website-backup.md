# 新北官方網站同輪備援

`NTPC_WEBSITE_BACKUP_ENABLED` 預設關閉，只有精確字串 `true` 啟動。未設定、`false`、`TRUE` 或 `1` 均不啟用。這次實作與離線測試不代表正式啟用，沒有修改 `.env` 或部署環境。

## 擷取流程

1. 追蹤週期從 Subscription Context 的實際活躍站點取出新北路線，排除未訂閱、窗外及深度休眠站點。今日啟用但沒有活躍站點的路線不會送往網站。
2. Facade 先套用縣市熔斷與暫停規則，主來源仍是新北開放資料 API。顯式 `overrideUrl`、沒有必要新北路線或新北被暫停時，不做網站查詢。
3. 啟用後，所需路線的主來源位置樣本須有可解析 GPS 時間，年齡介於未來 60 秒至過去 300 秒（含邊界）。無時區新北日期依台灣 `+08:00` 解析；已有 ISO 時區保留偏移。不接受不存在的日期、非法時間或模糊字串。
4. 主來源失敗、缺路線或所需路線只有不可靠／過期時間時，同輪一次 POST `https://crd-rubbish.epd.ntpc.gov.tw/WebAPI/GetArrival`，表單 `LineID` 只包含缺口路線。主来源維持既有兩次／每次 12 秒重試，網站一次／5 秒逾時、零重試。
5. 網站只採用指定路線、非空車號、台灣界限內座標，且 `BarCode` 為路線 ID、`000005` 或 `000007` 的執勤車輛。未知狀態、暫離、回場、路況障礙與前往焚化廠均拒絕。相同路線／車號去重，有效主來源始終優先。
6. 網站頂層 `TimeStamp` 嚴格解析為台灣回應時間，須通過相同新鮮度界限。採用資料標記 `source: 'ntpc-website'`、`timestamp_kind: 'response'` 及 `source_timestamp`，不寫入 `truck.time` 或假造速度。`Diff` 是班表偏差、`PointTime` 是表定時間；`Point.Arrival` 也不是現在車輛的 GPS 採樣時間。
7. 車輛經原有 Arrival Matcher、自適應圍欄、進場方向、班表、車速、信任 linid、防重複、通知與配額護欄處理。網站回應不直接產生通知。

新北 `sourceStats` 始終一筆，`url` 保持 canonical 開放資料 URL；`primary`、`fallback` 診斷顯示請求路線、採用數、拒絕原因與錯誤。主來源連線成功時，網站失敗只記部分錯誤，不增加新北縣市連線失敗；主來源失敗而網站有採用車輛時視為成功；兩端無法提供成功來源時才沿用既有失敗／暫停機制。其他城市資料保留。

## 呼叫契約

`fetchActiveTrucks({ requiredNtpcRouteIds, now, ntpcWebsiteBackupEnabled, ...options })` 接受數字字串路線陣列並去空白、去重、排除分隔符及非數字；缺省陣列保持舊行為。`now` 必須是真實 UTC 瞬間的有效 `Date`，缺省或無效值採呼叫當下時間。可選 boolean 旗標供離線測試控制，未提供時讀環境變數。

`fetchTrucksWithRetry(dateStr, overrideUrl, targetCities, options)` 轉交同三個選項與原有 `timeoutMs` 選項。追蹤週期將台灣 `dateStr`、`hour`、`minute` 還原為帶 `+08:00` 的真實瞬間，不將已偏移八小時的 `taiwanNowInfo.now` 當 UTC；欄位無效時採真實呼叫時間。

## 三個不同的完成狀態

- **離線實作驗證**：本機 fixtures 與 HTTP／DB mocks 通過，所有真實網路被拒絕。這只能證明程式契約，不能證明網站座標正在更新。
- **服務實證驗證**：另行核准後，於既有路線真實服務時段執行唯讀公用網站探查，保存多個連續原始樣本、抓取 UTC 瞬間、路線、車號、狀態、座標變化、歷史實際 Arrival 與對照來源，在 `docs/reports/` 留下報告。必須分開標示回應時間與位置時間，證明座標更新與真實執勤相關，且延遲符合五分鐘容忍值。週日空車號／零座標樣本不算有效歷史實績。只有 TimeStamp 更新而座標更新無法證明時，繼續關閉。
- **正式部署啟用**：服務实證與雙軸審查完成、使用者另行核准後，才設定 `true` 並部署。新地點仍須遵循原有历史實際清運資料驗證規範；這項功能沒有新增地點或訂閱。

啟用首批服務輪次須檢查來源、路線覆蓋、拒絕原因及熔斷狀態。發現座標凍結、錯誤路線或異常大量拒絕時，將旗標回滾 `false`，保留審計證據；取消旗標即恢復既有 intake 行為。兩端資料缺口、過期座標與輪詢跨站仍可能漏報，不能保證不漏報。

禁止為本功能的離線測試透過 production handler／dry-run 觸發 LINE；用量查詢也只能 mock。本次沒有呼叫真實 LINE、DB 或公用網站。
